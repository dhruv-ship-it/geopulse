There is no oracle for incident identity - "which incident is this" is a policy, not a
computation - so this asserts what must be true of the answer whatever the policy decides,
after EVERY event of EVERY sequence:

  1. every active zone is in exactly one component
  2. two zones share a component iff a path of active adjacent zones connects them,
     checked against a BFS written independently of both connectivity implementations
  3. no OPEN incident is below INCIDENT_MIN_ZONES, and no component at or above the
     minimum is without an incident
  4. replaying the same sequence produces a byte-identical event stream, ids included

The seed is pinned (42), so this is the same set of sequences on every machine.

Configuration: windowMs 60000, compactionIntervalMs 5000, minZones 3, closeGraceMs 20000,
14-zone universe over random symmetric graphs, plus a 5x4 lattice, plus runs at
closeGraceMs 0 and at minZones 1.

WHAT THIS RUN FOUND
The first run of these properties failed with "OPENED for INC-... after it was CLOSED".
An incident that closes and an identical seed set that reopens at the SAME event-time
millisecond mint the same id, because the preimage is (seed members + openedAt) and the
watermark had not moved. Fixed by keeping the ids retired at the current watermark instant
and disambiguating against them; the set is pruned as soon as event time moves past them,
so it holds one instant's closures rather than a growing graveyard. See ADR-003.
